# 2026-11-25 开发记录

## UI 长尾 U-04：选框/手柄/对齐参考线闭环（用户「继续」）

### 背景

- 按 `roadmap/UI_TAIL_SCHEDULE.md` A 档第 4 批推进。DoD：预览旋转手柄被遮挡的布局修正 + 参考线从纯视觉升级为可吸附 + 浏览器拖动写回截图验收。
- 探查确认：选框与四角/三边手柄早已端到端写回 core transform；旋转手柄因 `top: box.top% - 24px` 且 stage `overflow:hidden`，满幅元素贴顶时被裁；参考线只做"吸附到画布中心 50%"一种，且画在选框容器内部（坐标系错误，实际画在选框中心而非画布中心）。

### 实现

- `preview-transform-model.ts`：新增 `snapBoxToCanvas(box, thresholdX, thresholdY?)` 纯函数，垂直依次尝试 left→0 / center→50 / right→100，水平依次尝试 top→0 / center→50 / bottom→100，取阈值内最近锚点；新增 `SnapGuides`（含 `verticalAt`/`horizontalAt` 画布百分比位置）与 `NO_SNAP_GUIDES`。
- `preview-section.tsx`：
  - 旋转手柄从 `translate(-50%, calc(-50% - 24px))` 改为 `top: max(calc(box.top% - 24px), ICON_HANDLE_RADIUS px)` + `translate(-50%,-50%)`，保留经典版外移视觉的同时保证贴顶时仍可见；
  - 参考线移到 stage 层（画布坐标系），按 `verticalAt`/`horizontalAt` 定位，不再画在选框中心；
  - 吸附阈值横纵分别按 stage 宽高换算；旋转模式只改角度，不再误触发位置吸附。

### 验收

- tsc 0、vitest **43 文件 / 540 项**（+10）全绿、vite build 成功。
- ego(lite) 1600×1000：
  - 选中 clip-intro 后 8 个手柄齐全，旋转手柄 `top=63.2px` 与 stage 顶一致、完整可见；拖拽到画布右下方写回 `rotate=117.6°`。
  - 拖右边缘手柄缩小选框后左移，vertical/horizontal 参考线均出现在 `0%`，`boxWhileDragging.cx=514.08`（吸附到左边缘），松手后 `positionX=-79.86 / scaleX=0.50` 写回。
  - 截图 `roadmap/oc-rotate-handle.png` / `roadmap/oc-snap-guides.png`。
- 台账：`FEATURE_PARITY.md` §4 选框行 🟡→✅，统计逐行核算 45/2/5/15；`UI_REPLICA_PLAN.md` §8 追加。

### 踩坑

- 测试"阈值外不吸附"最初用默认 box（中心恰好 50%），阈值再小也会命中中心吸附；改为 `left:20/top:20` 远离所有锚点。
- 浏览器验收中每次 transform 写回后选中态会被清空，导致后续手柄消失；脚本需在每步拖拽后重新点击片段选中。
- 从手柄 DOM 反推选框中心比依赖 `parentElement` 更稳健。
- 用元素 `textContent === "clip-intro"` 的中心坐标点击比固定屏幕坐标可靠（布局随视口变化）。

### 边界

- 吸附仅覆盖画布三锚点（0/50/100），未扩展元素间对齐；参考线为拖拽期视觉反馈，写回发生在 mouseup。
- 不改 core、不改 additive-only 写回契约；旋转吸附沿用既有 90° 步长逻辑。

## UI 长尾 U-05：拖拽排序跨轨（用户「继续」）

### 背景

- 按 `roadmap/UI_TAIL_SCHEDULE.md` A 档第 5 批推进。DoD：片段可跨轨拖放，跨轨后片段换轨，撤销回原位。
- 探查发现比排期预估更深：`CoreElement` 无轨道字段、`elements` 扁平且只覆盖 main；落轨/移动回调无轨道维度；非 main 轨被 `readOnly` 阻断移动/裁剪。

### 实现

- `editor-ui.tsx`：`CoreElement` 增可选 `trackId?: string`（缺省 main，保持旧数据兼容）。
- `element-model.ts`：新增 `moveElementToTrack(clips, id, startTicks, targetTrackId)` 纯函数，只改 `startTime` 与 `trackId`；移回 main 时删除字段。
- `timeline.tsx`：`TimelineDrag` 增 `sourceTrackId/targetTrackId`；新增 `trackIdAtClientY(clientY)` 按指针 Y + 轨道高度累计定位目标轨；`onDropAsset`/`onMoveClip` 回调增目标轨参数；移除 `readOnly` 对移动/裁剪的阻断；松手时时间或轨道任一变化即提交。
- `editor-page.tsx`：`handleAddAsset`/`handleTimelineDrop` 透传目标轨并在落轨元素上写 `trackId`；`timelineTracks` 按 `trackId` 分轨渲染；跨轨移动走统一 `applyClipEdit` + `moveClipClamped` 并记入 U-02 快照，选中态保持。

### 验收

- tsc 0、vitest **43 文件 / 547 项**（+7）全绿、vite build 成功。
- ego(lite) 1600×1000：初始 `clip-intro` 在 main，拖到 audio 后 main 只剩 `clip-body`；Ctrl+Z 撤销后 `clip-intro` 回 main 原位。截图 `roadmap/oc-cross-track.png`。
- 台账：`FEATURE_PARITY.md` §6 拖拽排序行 🟡→✅，统计逐行核算 46/1/5/15；`UI_REPLICA_PLAN.md` §8 追加。

### 踩坑

- TS 报错 boolean 不能赋给 string：`startDrag` 第四参由 `readOnly: boolean` 改为 `sourceTrackId: string` 后，播放头调用漏改为传 `''`、裁剪手柄漏改为传 `track.id`。
- 跨轨选中态需经 `applyClipEdit(..., selectedAfter)` 显式传入，否则跨轨后选中丢失。

### 边界

- 仅会话内跨轨：JSON 写回搬轨触 additive-only 边界（core 契约只覆盖 main 轨道归属），留 U-06/U-07 决策。
- 三轨结构本身仍固定（overlay/main/audio），未做动态子轨。

## UI 长尾 U-06：动态新增轨道 + 写回允许新实体（B 档，用户选 B）

### 背景

- 用户问「写回边界优劣势」，解释选 A（additive-only 安全但不完整）与选 B（允许新增轨但需控兼容风险）后，明确选 B：「功能齐全，不能只有 3 条轨道」。
- 核心决策：用显式 `allowNewTracks` 开关（默认 false 保持 additive-only）+ 往返测试控风险，不直接改默认契约。

### 实现

- **core（`project_compat.rs`）**：新增 `WriteOptions{allow_new_tracks}`（serde camelCase、默认 false）+ `write_classic_project_with_options`；原 `write_classic_project` 保留为默认包装器。新轨按 trackType 归入 overlay/audio 数组（main 保持单条不新增），新增元素/可选字段用 `build_element_value`/`build_track_value` 构造，未知字段原样保留。
- **WASM**：`write_classic_project_wasm` 请求解析可选 `allowNewTracks`（类型错误按 false 宽容处理）；重编 wasm 产物。
- **Web**：适配层接口加第三参；`project-autosave` 加可选 `ExtraTrackState[]`（只存 id/trackType/muted?/hidden?，非法类型整条作废）；`project-write` 把新轨追加到首场景并传开关；`timeline.tsx` 工具栏加类型下拉 + `plus` 按钮；`editor-page` state/autosave 恢复/分轨渲染/header 计数同步。

### 验收

- tsc 0、vitest **43 文件 / 552 项**（+5）全绿、`project_write` Rust 14/14、WASM 契约 132/132、vite build 成功。
- ego(lite)：新增 text 轨→状态栏提示→刷新后 6 轨（原 3+新 3）→项目菜单点「写回经典版 JSON」下载 `oc-u06-writeback.json`，验证 overlay 含全部新轨、main/audio 不变、`timelineViewState` 保留、默认开关写回仍返回 `ENTITY_NOT_FOUND`。截图 `oc-new-track.png` / `oc-new-track-reload.png`。
- 台账：FEATURE_PARITY §3 三轨结构 🟡→✅，逐行核算 47/0/5/15；UI_REPLICA_PLAN §8、UI_TAIL_SCHEDULE U-06 决策状态已更新。

### 踩坑

- **WASM 编译找不到 core/std**：PATH 里独立的 1.96 cargo 抢在 rustup proxy 前，1.96 的 wasm target 空；`local/` 被 override 到 1.97 且 1.97 的 wasm libdir 完整。解法：用绝对路径 `C:\Users\ht182\.rustup\toolchains\1.97.0-x86_64-pc-windows-msvc\bin\cargo.exe` 编译，再 `wasm-bindgen --target web` 生成 glue。
- 顶栏 header 轨道数取自 `session.projectTrackCount`（原始值），新增轨后不更新；改为 `+ extraTracks.length`。
- autosave 的 IndexedDB store 名是 `entries`，且存入的是 JSON 字符串（读时需二次 `JSON.parse`）——验收脚本只读一层导致误判 NO_EXTRA。
- ego(lite) 选择器 `.classic-timeline-label` 不存在；顶栏按钮在 `button[title='项目菜单']` 下拉里，写回按钮文案是「写回经典版 JSON」。

### 边界

- main 保持单条对象，新增轨一律进 overlay/audio 数组（经典版 schema 约束）。
- U-05 跨轨搬移的 JSON 写回（元素换轨）与 overlay/audio 轨编辑写回留 U-07。
- 新轨不纳入 U-02 撤销快照（排期未要求；autosave 可持久化）。
