## 启动脚本修复：start-web.bat 端口堆积（用户指出「先杀进程」「启动bat要改吧」）

### 背景

- 浏览器验收多次 `Start-Process bun run dev` 不清理，导致 5173/5174/5175/5176/5177 堆积多个 dev server。用户要求先杀进程并修启动脚本。
- 原 `start-web.bat` 只按 `%DEV_PORT%` 端口杀单个 PID，Vite 抢不到端口会自动换到 5174/5175，旧实例漏杀。

### 实现

- `start-web.bat` 两阶段清理：① 新增 `clean-vite.ps1` 按「命令行含本项目 `vite.js` 路径」杀所有相关进程（端口无关，覆盖换端口实例）；② 端口监听兜底（覆盖非标准启动）。杀完 `timeout 2` 后再确认端口释放，否则报错退出。清理逻辑委托给 ps1 是为避开 bat 内联 PowerShell 的层层引号反斜杠转义坑。
- `clean-vite.ps1` 接收 `-Needle` 参数，用 `Get-CimInstance Win32_Process` 的 `CommandLine.Contains($Needle)` 匹配并 `Stop-Process -Force`，try-catch 不吞异常。
- README 补 Windows 双击启动说明。

### 验收

- 实测重复运行 bat：先杀掉 5173 旧实例再在 5173 起新实例，5174~5177 无残留；再制造 5174 换端口残留，bat 一次清掉两个 PID 后只留 5173。最终 HTTP 200。
- 日志显示真实 PID（`Killed Vite process PID=32500` 等），`for /f` 用 `tokens=2 delims==` 从 ps1 的 `KILLED=PID` 行取 PID。

### 踩坑

- **Windows bat 中文注释坑**：系统活动代码页是 65001（UTF-8），但 cmd 解析 bat 时 UTF-8 中文注释行会被从中间截断成命令，报 `'...' is not recognized`。转 GBK 反而更糟（cmd 用 UTF-8 读 GBK 全乱码）。最终 **bat 注释与 echo 全改 ASCII**，并在文件头注明原因——这是 Windows 批处理的编码限制，与「注释用中文」偏好冲突时以脚本可运行性优先。
- `for /f` 内联 PowerShell 里 `%VITE_ENTRY:\=\\%` 变量替换会插入双反斜杠导致 `-like` 匹配失败；`%VITE_ENTRY%` 原样也不稳（单引号嵌套）。改独立 ps1 文件 + `-Needle "%VITE_ENTRY%"` 传参解决。
- `Start-Process -WindowStyle Hidden` 启动的 bat，Vite 会在 ready 后退出（隐藏窗口 stdin 关闭）；正常双击/非隐藏方式稳定。验收须用非隐藏方式。
- `Remove-Item` 走回收站会因日志被运行中进程占用而失败；用 node `fs.unlinkSync` 可删未占用文件，占用中的须先停 wrapper。
- 当前 server 由 bat 在非隐藏窗口启动，日志重定向到系统临时目录 `opencut-devserver.log`，不污染项目根目录。

## UI 长尾 U-08：双击文字就地编辑（用户「继续」，A 档收尾）

### 实现

- `preview-text-edit-model.ts`：纯函数 `initialTextDraft`/`shouldCommitText`/`textEditKeyAction`（Enter 提交、Shift+Enter 换行、Escape 取消、其余继续输入），10 项单测。

- `editor-page.tsx`：仅 `elementType==='text'` 时传 `textContent`（content ?? params.content）与 `onTextChange={(c) => applyPropertyPatch({ content: c })}`，复用既有写回链路（自动同步 params.content + U-02 历史 + autosave）。

### 验收

- tsc 0、vitest **44 文件 / 570 项**（+10）全绿、vite build 成功。

### 踩坑

- 文字在 canvas 上，`document.body.innerText` 读不到编辑结果——验收须查 IndexedDB autosave 的 `elements[].content`，不能用 DOM 文本判断。
- 双击 stage 会先触发选框 mousedown 拖拽，transform 写回后清空选中态；验收用 `dispatchEvent(new MouseEvent('dblclick'))` 绕过鼠标按下，生产交互中用户直接双击文字仍可用（编辑器在 dblclick 时进入）。
- contentEditable 不能用受控 `value`，必须 useEffect 写 `innerText` 并手动把光标移到末尾，否则每次按键重渲染会把光标顶回开头。
- 属性面板默认 tab 未必是 Text，`textarea` 查询为空不代表没同步——面板与预览共享 `elements` state，`applyPropertyPatch` 写回即同步。
