# 2026-11-17 开发记录

## W-12 第四批 · WIT 契约层（用户「继续」，路线 B 第二步）

### 背景与关键决策（官方一手查证，不凭感觉）

- 用户上一批明确「先做 wasmi 运行时 + 细粒度权限，WIT 下一批做」，本批按约定接 WIT。
- 动手前按用户规则查官方文档定论：
  - wasmi 官方仓库 `wasmi-labs/wasmi` README 特性表只写 `wasip1`（经 `wasmi_wasi`），**无 component model / WASI Preview 2 / WASI 0.2 条目**；
  - 组件模型 issue `wasmi-labs/wasmi#897`「Implement the Wasm component-model proposal」仍开放；
  - 第三方 `wcmp-wasm-core-wasmi` 以「Component Model Polyfill 的 wasmi 后端」形态存在，反证 wasmi 核心不原生运行组件。
- **判定**：wasmi 2.0 原生只执行 core WebAssembly module。故不引入 wasm-tools / wit-bindgen / cargo-component（本机均未安装，rustup target 仅 `wasm32-unknown-unknown`），**不谎称完整组件运行时**；改为把 WIT 作为接口契约（IDL）单一事实来源，完整 component model 明确后置。

### 交付

- 新建 `local/crates/ocx-plugin-host/wit/ocx-plugin.wit`：按官方 WIT 语法书写的内嵌契约——`package opencut:plugin@1.0.0`、`interface effects { brightness }`、`interface commands { ping }`、`world plugin { export effects; export commands; }`，用 kebab-case 标识符与 `///` 文档注释。
- 新建 `local/crates/ocx-plugin-host/src/wit.rs`：零第三方依赖的轻量解析器——`strip_comments`（`//` / `/* */`）、`normalize_braces`（支持官方合法的单行块 `world p { export e; }`）、kebab-case 标识符校验（无下划线/连续连字符/首尾连字符/数字开头）、导出名映射 `get-info → effect_get_info`、`has_effect`/`has_command` 精确白名单查询；6 项内联单测。
- `runtime.rs`：`LoadedPlugin` 内嵌 `WitContract`（`load_plugin_with_fuel` 解析默认契约，失败即 `INVALID_WIT` 拒绝、不静默降级）；`authorize()` 在「manifest 白名单 + 权限」之外增加**第二层 WIT 契约白名单**，导出名必须能在内嵌 `.wit` 的 effects/commands 接口找到（kebab-case 逻辑名经 `to_export_name` 映射为 snake_case 导出名后比对）。沙箱从五层变六层。
- `model.rs`：additive-only 追加 2 个稳定错误码 `INVALID_WIT` / `WIT_EXPORT_NOT_DECLARED` 及 `code()` / `Display` 映射。
- `lib.rs`：`pub mod wit` + re-export `DEFAULT_WIT` / `WitContract` / `default_contract` / `parse_wit`。
- `tests/runtime.rs`：新增 W07 端到端负向测试——WAT 模块真实导出 `effect_mystery`，Registration 声明 `mystery`、授予 `effect` 权限，加载成功但调用被 `WIT_EXPORT_NOT_DECLARED` 拦截，证明 WIT 是独立于 manifest 的第二道闸。
- 文档：`PLUGIN_CASES.md`（W-12 第四批 W01~W07 + 调研结论 + 稳定码 + 诚实边界）、`NOTICE.md`、`PRIORITY.md`（W-12 进度与 core 阶段结论）、`HOTSPOTS.md`（H07 证据 + 变更记录）、`UI_REPLICA_PLAN.md` §8、看板 r61→r62（`dashboard-data.js` / `dashboard.html` / `dashboard.test.cjs`）。

### 踩坑与修复

1. `str::replace` 第二参数需 `&str` 而非 `char`：新增 `WASM_NAME_REPLACEMENT: &str = "_"` 常量。
2. 官方 WIT 合法的单行块 `world plugin { export effects; }` 在初版逐行状态机里解析失败（export 与 `{` 同一行被跳过）：新增 `normalize_braces` 把花括号换行归一化（`{` 保留行尾、`}` 换行），既支持单行块又不破坏声明识别。
3. 3 个注释标记常量（`LINE_COMMENT` / `BLOCK_COMMENT_START` / `BLOCK_COMMENT_END`）未使用告警：strip_comments 直接用字符扫描，删除这 3 个常量。

### 验证结果

- `cargo test -p ocx-plugin-host`：wit 单元 **6/6** + runtime **8/8** + stability **13/13** 全绿。
- `cargo test --workspace`：全工作区所有 crate 测试全绿，无 FAILED / error。
- `cargo fmt --all` 后复测全绿；`cargo clippy -p ocx-plugin-host --all-targets -- -D warnings` 零告警。
- 6 项单元覆盖：默认契约解析、注释忽略 + 单行块、4 种结构错误（缺 package / export 空 / export 未知接口 / 接口空）、5 种非法标识符、导出名映射、白名单精确查询。

### 诚实边界（写入各文档）

- 本批是 **IDL + 双重导出白名单**，与现有 core wasm ABI（`ocx_alloc` / `(ptr,len)→i64`）完全兼容；浏览器侧 `plugin-runtime.ts` 与 wasmi 侧共用同一份契约语义。
- **未实现**：WebAssembly component model 组件编解码、canonical ABI、wit-bindgen 生成绑定、WASI Preview 2/3（wasmi 不支持）；WASM glue / TS 未新增 wasmi 或 WIT 入口（只交付 Rust core 契约能力，避免重复重编 wasm）。
- 完整 component model 若要落地，需另选运行时（Wasmtime 等）或经 polyfill，另评估，不在本批范围。

## W-12 第五批 · 声明式权限（用户「继续」，路线 B 收尾）

### 背景与决策

- 路线 A（tsc 清零）、C（PNG/WAV）、B1（wasmi）、B2（WIT 契约层）均已完成。W-12 暂停列表里"声明式权限"是最后一个不依赖 H01、不涉及产品化 UI 的非阻塞项，据"core 达标前先补 DoD"约束推进。
- 按用户规则查 capability-based security 最佳实践，共识：deny-by-default（manifest 显式声明）、host 仅注入授予的能力函数、函数内再次按 scope 校验具体资源、不暴露原始文件/网络句柄。据此**不引入通用 WASI 文件/网络能力**，只做资源级 scope + 一个受控能力函数示例。

### 交付

- `model.rs`：`PluginManifest` / `Registration` additive-only 新增 `permissionScopes: BTreeMap<能力名, Vec<scope>>`（缺省空 = deny-by-default，兼容旧 JSON）；新增 3 稳定错误码 `UNKNOWN_SCOPE_CAPABILITY` / `INVALID_SCOPE` / `SCOPE_DENIED` 及 code/Display 映射；新增常量（资源型能力 `media-read`、通配符、分隔符、256B 长度上限、64 条上限）。
- 新建 `src/permissions.rs`：零依赖纯函数模块——`validate_scope`（`ns:resource` / `ns:*`，禁部分通配/空段/超长）、`validate_permission_scopes`（能力须已声明且资源型、条数与格式合法）、`scope_allows` / `granted_allows`（精确 + 前缀通配匹配，deny-by-default）；4 项单测。
- `registry.rs`：`check_manifest` 能力校验末尾接入 scope 校验；Registration 透传 `permission_scopes`。
- `runtime.rs`：`Store<()>` → `Store<HostState>`；新增 `HostState { granted_scopes, resources }`；新增 `load_plugin_with_resources` 与共用 `instantiate`：仅当授予 scope 非空时用 `func_wrap` 注入受控 `ocx.resource_len(ptr,len)->i64`（读插件内存 key → 按 scope 校验 → 返回 host 资源字节数，越权返回 `Result::Err(trap)`，不存在返回 -1）；`map_trap` 按 `scope_denied:` 前缀映射 `SCOPE_DENIED` 并提取资源名；旧 `load_plugin` / `load_plugin_with_fuel` 零导入语义完全不变。
- 新建 `tests/declarative_permissions.rs`：6 项端到端（精确授权、越权拒绝、通配授权、零导入仍拒能力导入、manifest 清单校验、旧 manifest 兼容）。
- 文档：`PLUGIN_CASES.md`（W-12 第五批 D01~D06 + 调研 + 错误码 + 边界）、`NOTICE.md`、`PRIORITY.md`、`HOTSPOTS.md`（H07 + 变更记录）、`UI_REPLICA_PLAN.md` §8、看板 r62→r63。

### 踩坑与修复

1. `json!` 宏动态 key 必须加括号 `{ (CONST): value }`，否则被当字面字符串 key。
2. WAT `data` 段内嵌 JSON 的双引号需转义为 `\"`（Rust 侧 `OUTPUT_JSON.replace('"', "\\\"")`）。
3. WAT 规范要求 `import` 必须位于 `memory`/`data` 之前，否则 wasmi 报 "import after memory"，且被 `map_trap` 的文本匹配误映射为 `DISALLOWED_IMPORT`，极具误导性。
4. 能力函数检查 `ptr <= 0` 为空指针，测试 WAT 的 key 必须放非零内存偏移（改用偏移 16）。

### 验证结果

- `cargo test -p ocx-plugin-host`：permissions 4/4 + wit 6/6 + declarative 6/6 + runtime 8/8 + stability 13/13 全绿。
- `cargo test --workspace`：全绿，无 FAILED/error。
- `cargo fmt -p ocx-plugin-host -- --check` 0；`cargo clippy -p ocx-plugin-host --all-targets -- -D warnings` 零告警。
- 期间 `cargo clean -p ocx-plugin-host` 后 `roadmap/*.png` 全部从磁盘消失（原因未明），已从 HEAD 全部恢复 17 张，git status 无 PNG 删除残留。

### 诚实边界

- 本批是 **Rust core 侧 capability 权限原型**：验证"显式声明 → 按授予注入 → 函数内按 scope 校验"闭环，受控函数只返回 host 注入资源的字节数，不提供真实文件/网络访问。
- 未实现：通用 WASI P1/P2 能力、文件系统/网络 scope、跨调用资源句柄；WASM glue/TS 未新增入口（避免重复重编 wasm）；完整 component model 仍需另选运行时/polyfill，后置。
