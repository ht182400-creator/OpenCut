## W-12 第五批 · 声明式权限（用户「继续」，路线 B 收尾）

### 背景与决策

- 路线 A（tsc 清零）、C（PNG/WAV）、B1（wasmi）、B2（WIT 契约层）均已完成。W-12 暂停列表里"声明式权限"是最后一个不依赖 H01、不涉及产品化 UI 的非阻塞项，据"core 达标前先补 DoD"约束推进。
- 按用户规则查 capability-based security 最佳实践，共识：deny-by-default（manifest 显式声明）、host 仅注入授予的能力函数、函数内再次按 scope 校验具体资源、不暴露原始文件/网络句柄。据此**不引入通用 WASI 文件/网络能力**，只做资源级 scope + 一个受控能力函数示例。

### 交付

- `model.rs`：`PluginManifest` / `Registration` additive-only 新增 `permissionScopes: BTreeMap<能力名, Vec<scope>>`（缺省空 = deny-by-default，兼容旧 JSON）；新增 3 稳定错误码 `UNKNOWN_SCOPE_CAPABILITY` / `INVALID_SCOPE` / `SCOPE_DENIED` 及 code/Display 映射；新增常量（资源型能力 `media-read`、通配符、分隔符、256B 长度上限、64 条上限）。

- `registry.rs`：`check_manifest` 能力校验末尾接入 scope 校验；Registration 透传 `permission_scopes`。
- `runtime.rs`：`Store<()>` → `Store<HostState>`；新增 `HostState { granted_scopes, resources }`；新增 `load_plugin_with_resources` 与共用 `instantiate`：仅当授予 scope 非空时用 `func_wrap` 注入受控 `ocx.resource_len(ptr,len)->i64`（读插件内存 key → 按 scope 校验 → 返回 host 资源字节数，越权返回 `Result::Err(trap)`，不存在返回 -1）；`map_trap` 按 `scope_denied:` 前缀映射 `SCOPE_DENIED` 并提取资源名；旧 `load_plugin` / `load_plugin_with_fuel` 零导入语义完全不变。
- 新建 `tests/declarative_permissions.rs`：6 项端到端（精确授权、越权拒绝、通配授权、零导入仍拒能力导入、manifest 清单校验、旧 manifest 兼容）。

### 踩坑与修复

2. WAT `data` 段内嵌 JSON 的双引号需转义为 `\"`（Rust 侧 `OUTPUT_JSON.replace('"', "\\\"")`）。

## 新增 start-web.bat（用户要求「启动前 kill 老进程」）

- 在项目根新建 `start-web.bat`：启动 web 前先终止端口 5173 上的老进程，再启动 Vite。
- 实现：可配置项提取为常量（`DEV_PORT=5173`、`WEB_DIR=%~dp0apps\web`、`VITE_ENTRY`）；用 `netstat -ano | findstr ":<port> " | findstr LISTENING` 取 PID 后 `taskkill /F /PID`（精确按端口，不误杀 3000/3001 等其他服务）；再用 PowerShell `Get-CimInstance Win32_Process` 按命令行含 `vite.js` + `--port 5173` 清理抢不到端口的孤儿进程（Windows 自带，无额外依赖）；`cd /d` 到 `apps\web` 后 `node vite.js dev --port 5173`。

- 验证：首次启动 HTTP 200；二次启动 kill 老 PID → 新 PID 监听，始终只有 1 个 vite 实例、HTTP 200；端口 3000/3001 的其他服务不受影响。

## 波形抽样 TOO_MANY_PCM_SAMPLES 修复（用户实测 2 分钟视频触发）

### 现象与根因

- 用户导入「一支毛笔的旅行.mp4」（2:00）后页面顶部红字：`波形抽样失败：Rust core 调用失败：生成波形失败：TOO_MANY_PCM_SAMPLES：PCM 样本数超出上限`。
- 根因：`ocx-render/src/waveform.rs` 的 `MAX_PCM_SAMPLES=4_096_000`（≈85 秒 @48kHz）；2 分钟音频 576 万样本超限。调用链 `editor.tsx` effect → `mixdownToMono(audio)` → `adapter.waveformPeaksFromPcm(mono)` → core。
- 关键发现：`waveform.rs` 第 15 行注释写「超出按等距降采样处理」，但实现（第 91 行）直接返回错误——注释与实现不一致，说明原设计就想自动降采样但漏实现。

### 修复（TS 侧降采样，不动 core ABI/wasm）

- `audio.ts`：新增 `WAVEFORM_MAX_PCM_SAMPLES = 4_096_000`（与 core 对齐，注释标明来源）与纯函数 `downsampleForWaveform(samples, maxSamples?)`——超限时等比分桶、每桶取绝对值最大保留符号（与 core 峰值检测语义一致）、非有限值按 0、未超限原样返回（同引用不复制）。
- `editor.tsx`：波形 effect 在 `mixdownToMono` 后插入 `downsampleForWaveform`，同步更新注释。
- 决策：在 TS 侧修而非改 core 上限或 core 内部降采样——避免重编 wasm、不动契约/测试，符合「WASM glue 不新增入口」既有边界。

### 验证

- tsc `--noEmit` 0 错误；vitest 24 文件/242 项全绿（新增 5 项降采样用例：不降原样、等比分桶峰值保真、满幅保留、边界、非有限值）；vite build 成功（1.84s）。
- 浏览器动态 import 真实模块端到端：构造 576 万样本 PCM → `downsampleForWaveform` 降到 409.6 万 → `wasm.waveform_peaks_from_pcm` 返回 16 峰值（0.5 振幅→128），无 TOO_MANY_PCM_SAMPLES；满幅尖峰保真验证（255 且仅 1 bin 非零）。
- 截图 `roadmap/oc-ui-waveform-fix.png`（53KB，页面无红字错误）。

### 踩坑

- `Float32Array` 存字面量 0.8 实际是 0.800000011920929，`toEqual` 严格比较失败 → 改 `toBeCloseTo`（测试写法问题，非实现 bug）。
- 仍用本地二进制跑前端验证（`node node_modules/...`），未再触发 pnpm exec 污染。
