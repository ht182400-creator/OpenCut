## 关键踩坑：GPUI 周期任务（耗时最多，已解决）

- 现象：播放任务启动后播放头长期停在 0；加诊断标记证实 task **首次 poll 成功**（写入 SPAWNED），但 `timer.await` 之后不再推进。
- 依次尝试均失败：
  1. `Context::spawn` + `cx.background_executor().timer(...).await`（构造期 spawn、detach、持有 task 句柄三种变体）；
  2. 移到 App 级 `cx.spawn`；
  3. `smol::Timer::after(...)`（GPUI 自身 util.rs 用的模式）；
  4. render 内 `window.refresh()` 帧循环 + `Instant` 计时——只读推进 1 帧。
- 根因两条（均有源码/官方依据）：
  - `Window::refresh()` 内部 `if self.invalidator.not_drawing()`，**绘制中调用被忽略**，所以 render 内 refresh 形不成下一帧；
  - GPUI 官方周期任务模式要求更新实体后调用 **`cx.notify()`** 请求重绘——此前只 `state.advance_playback()` 未 notify，UI 不刷新且任务后续无驱动。
- 最终实现（`shell.rs`）：
  ```rust
  cx.spawn(async move |_this, cx| loop {
      cx.background_executor().timer(PLAYBACK_INTERVAL).await;
      let _ = timer_project.update(cx, |state, cx| {
          state.advance_playback();
          cx.notify();
      });
  }).detach();
  ```
  实机验收：4 秒推进 18 帧（0.60s / 帧 18），checksum 随帧变化，截图 `roadmap/oc-w14-playback.png`。
- 键盘事件端到端：Windows 下 `AppActivate` 可前置窗口，但浏览器会话反复抢焦点；WScript SendKeys / .NET SendKeys / SendInput 三种方式均未能把空格送进 GPUI 窗口（`last_shortcut` 始终为空）。**如实记录未复现**；快捷键分发逻辑已由 `apply_shortcut` 纯函数单测覆盖。
- 诊断残留（timer_fires / SPAWNED 标记 / smol 依赖）已全部清理。
