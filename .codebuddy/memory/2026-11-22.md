### 关键踩坑：GPUI 周期任务（耗时最多，已解决）

- 现象：播放任务启动后播放头长期停在 0；加诊断标记证实 task 首次 poll 成功（写入 SPAWNED），但 `timer.await` 之后不再推进。
- 依次尝试均失败：
  1. `Context::spawn` + `cx.background_executor().timer(...).await`（构造期 spawn、detach、持有 task 句柄三种变体）；
  2. 移到 App 级 `cx.spawn`；
  3. `smol::Timer::after(...)`（GPUI 自身 util.rs 用的模式）；
  4. render 内 `window.refresh()` 帧循环 + `Instant` 计时——只推进 1 帧。
- 根因两条（均有源码/官方依据）：
  - `Window::refresh()` 内部 `if self.invalidator.not_drawing()`，绘制中调用被忽略，所以 render 内 refresh 形不成下一帧；
  - GPUI 官方周期任务模式要求更新实体后调用 `cx.notify()` 请求重绘——此前只 `state.advance_playback()` 未 notify，UI 不刷新且任务后续无驱动。
- 最终实现（`shell.rs`）：
  ```rust
  cx.spawn(async move |_this, cx| loop {
      cx.background_executor().timer(PLAYBACK_INTERVAL).await;
      let _ = timer_project.update(cx, |state, cx| {
          state.advance_playback();
          cx.notify();
      });
  }).detach();
  ```
  实机验收：4 秒推进 18 帧（0.60s / 帧 18），checksum 随帧变化，截图 `roadmap/oc-w14-playback.png`。
- 键盘事件端到端：Windows 下 `AppActivate` 可前置窗口，但浏览器会话反复抢焦点；WScript SendKeys / .NET SendKeys / SendInput 三种方式均未能把空格送进 GPUI 窗口（`last_shortcut` 始终为空）。如实记录未复现；快捷键分发逻辑已由 `apply_shortcut` 纯函数单测覆盖。
- 诊断残留（timer_fires / SPAWNED 标记 / smol 依赖）已全部清理。

### 验收

- 截图 `roadmap/oc-w14-playback.png`：Timeline `0.60s / 3.00s · 帧 18 · 播放中`，Preview 帧 18 / 72000 ticks / checksum 与首帧不同。

## W-13 第三批：脚本标签页 UI（脚本控制台）

### 背景

- 用户多选项 C 项：补 W-13 路线图剩余项「脚本标签页 UI」。
- 探查结论：现有 MCP / Headless CLI 都是 stdio，浏览器侧无 HTTP 入口；不引入 sidecar，复用 `EditorAdapter`（I-01 唯一 core 入口）在浏览器进程内调用等价能力（`editor-adapter.ts` 已暴露全部 6 个可用方法，均为同步）。
- 为不破坏经典版 9-tab 像素基线，控制台放在 Settings tab 的 `settingsContent` 内，而非新增第 10 个 tab。

### 实现

- `script-console-model.ts`：8 项工具目录（对齐 MCP `ocx.*`，6 项浏览器可用、`ocx.render.batch/status` 标为不可用）；`findScriptTool` / `parseScriptArgs`（空文本按 `{}`、拒绝数组/null）/ `formatScriptResult`（Uint8Array/字符串/对象、500 字截断）/ `formatScriptError`。示例帧参数用 `SAMPLE_FRAME_DURATION_TICKS` 常量避免裸数字。
- `script-console.tsx`：受控 props `onExecute` / `disabled`；工具下拉（不可用项 disabled）、参数 textarea、执行按钮、日志区（50 条上限）；关键元素带 `data-testid` 便于验收。
- `script-console-dispatch.ts`：MCP 工具名 → `EditorAdapter` 同步方法映射（`capabilities` / `project.read` / `project.write` / `otio.import` / `otio.export` / `render.frame`），统一包成 Promise；参数缺失给中文友好提示；catch 记 `console.error` 详细日志后原样透传，不吞异常；batch/status 与未知工具显式抛错，不伪造结果。
- `routes/editor.tsx`：Settings tab 的 `settingsContent` 接入 `ScriptConsole`，`onExecute` 由 `createScriptExecutor(session.adapter)` 注入；会话未就绪时禁用。

### 踩坑

- TS 严格模式：`Record<string, unknown>` 不能直接断言为 `ProjectView` / `CoreFrameRequest`，需 `as unknown as` 双重断言（字段完整性交由 core 校验）。

- 浏览器验收时 `agent-browser click e43` 未生效：一是 ref 需 `@e43` 且 PowerShell 要加引号，二是 Base UI 标签对脚本点击不敏感，最终用 `eval` 直接触发 `[role=tab]` 点击；首张截图被意外弹出的菜单遮挡，重新展开控制台并滚动到可见区域后重截。
