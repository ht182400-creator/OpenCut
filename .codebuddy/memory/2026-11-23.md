- 用户「先做第一档，再做第二档」的第一档 B。探查确认 `EditorAdapter` 13 个方法中 `negotiate` / `pluginRegister` 只在契约测试出现，UI 完全未接线，W-11 能力协商与 W-12 插件注册成为「死代码能力」。
- 底层已全部就绪：示例插件 wasm `apps/web/public/fixtures/sample-plugin.wasm`（116,313 字节）、manifest `sample_plugin.json`、`plugin-runtime.ts` 的 `loadPluginModule` / `runEffect` / `runCommand`。

### 实现

- 新纯逻辑模块 `classic-ui/plugin-settings-model.ts`：集中示例 manifest / 协商请求 / 授予能力 / wasm 路径四个常量，提供 `formatNegotiation` / `formatRegistration` / `formatPluginCall` 中文格式化。
- 新组件 `classic-ui/plugin-settings-panel.tsx`：受控 props（`onNegotiate` / `onRegister` / `onRunEffect` / `onRunCommand` / `disabled`），折叠面板 + 4 按钮 + 50 条日志上限，全部回调 try-catch 中文错误提示，`data-testid` 齐全。
- `editor.tsx`：新增 `pluginInstanceRef`；`settingsContent` 追加面板，`onNegotiate` 调 `session.adapter.negotiate(DEFAULT_NEGOTIATION_REQUEST)`，`onRegister` 先 `pluginRegister(manifest, grants)` 再 `fetch(SAMPLE_PLUGIN_URL)` → `loadPluginModule` 存 ref，effect/command 按钮真实调用 `runEffect('brightness',{amount:0.25})` / `runCommand('ping',{value:7})`；顺手把过期的「半闭环」注释改为第一档 A 已闭环。
- 新测试 `plugin-settings-model.test.ts` 6 项（常量基线、协商兼容/缺能力、注册成功/失败、调用结果序列化与循环引用回退）。

### 验收

- Web vitest 35 文件 **437/437**（+6）、`tsc --noEmit` 0 错误、`vite build` 成功。
- 真实浏览器（Settings tab → 插件面板）：能力自检 → `[协商] 兼容 · schema 1 · OK`；注册示例插件 → `[注册] 成功：sample-effects@1.0.0 · schema 1` + 能力/effects/commands 三行；brightness → `[effect] {"brightness":0.5}`；ping → `[command] {"pong":7}`。截图 `roadmap/oc-w08-plugin-settings.png`。

### 踩坑

- `PluginRegisterResult` 要求 `denied` 字段（即使 `ok:true` 也要传空数组），测试补 `denied: []` 后 tsc 通过。
- Settings tab 的 `title="Settings"` 在 `[role=tab]` 上，首次用文本匹配失败；改用 title 属性定位。

### 诚实边界

- 示例插件只演示 `brightness` / `ping` 两个 handler 与 core manifest 校验，不覆盖真实文件/网络 scope（W-12 已登记未实现）。
- 插件实例存在 React ref 中，刷新页面后需重新注册（无持久化，符合插件系统的无状态定位）。

### 提交状态

- 已提交（`feat(web)` + `docs` 两笔），推送至 `origin` / `forgejo`，未触碰 `upstream`。

## 第一档 C + 页面定位拆分：`/core-lab` 验证台与 `/editor` 产品页分离

### 背景

- 第一档 C 本要把「evaluate 五种 kind」自检面板接进 `/editor` Settings；实现完成（vitest 446/446、tsc 0）后用户质疑「为何又是 editor，editor 不是要测试 core 的测试页面吗？」。
- 用户问答明确新方向：**新建 `/core-lab` 专做 core 验证，`/editor` 保留为经典版产品页；C 的自检面板移到独立验证页而非 editor Settings**。
- 拆分前 `/editor` 混挂三块 core 验证面板：ScriptConsole（W-13）、PluginSettingsPanel（W-11/W-12 第一档 B）、EvaluateSettingsPanel（第一档 C），与「经典版产品页」定位冲突。

### 实现

- 新路由 `apps/web/src/routes/core-lab.tsx`（Core 验证台）：
  - `createFileRoute('/core-lab')`，页面自身只做 adapter 初始化（`createEditorAdapter`）+ 回调注入，无项目/无 session 依赖——evaluate / negotiate / pluginRegister / 脚本工具均为无项目参数的 core 能力，因此验证台打开即可自检。
  - 三块面板全部迁入：ScriptConsole（`createScriptExecutor`）、PluginSettingsPanel（协商/注册/effect/command）、EvaluateSettingsPanel（五种 kind + 不编码反例）。
  - 所有 core 调用集中在页面层，符合 I-01 单一入口；常量（提示文案 / wasm 路径 / 注册参数）集中为命名常量；初始化与插件调用均 try-catch + 中文友好提示。
- `apps/web/src/routes/editor.tsx`：删除 `createScriptExecutor` / 三面板 / 插件常量 / `loadPluginModule` 等导入、删除 `pluginInstanceRef` state、删除 Settings 内三面板挂载（净移除 54 行），回归纯经典版产品页。
- `apps/web/src/routeTree.gen.ts`：补 `/core-lab` 路由条目（build 时生成器确认一致，无需手工维护）。
- 新增文件（第一档 C 逻辑，延续到 core-lab）：
  - `classic-ui/evaluate-settings-model.ts`：5 种 kind 可执行样例 + 不兼容导出反例，`checkEvalResult` 全分支断言逐字对齐 `editor-wasm.contract.mjs`。
  - `classic-ui/evaluate-settings-model.test.ts`：9 项（常量 / 序列化 / 全用例正反 / switch 覆盖）。
  - `classic-ui/evaluate-settings-panel.tsx`：受控 props，按钮触发 core → 断言 → 中文日志，50 条上限。

### 验收

- Web vitest **36 文件 / 446 项全绿**、`tsc --noEmit` 0 错误、`vite build` 两个产物成功；路由表 build 后仍含 `/core-lab`。
- 真实浏览器（agent-browser）打开 `/core-lab`：
  - evaluate 六按钮（含反例）逐项点击，**六项全部「通过」**：动画插值 value=5、放置 kind=existingTrack、命令 events=1、导出校验 ok=true、不编码 code=INCOMPATIBLE_CODEC、关键帧 frames=2 / linear。
  - 插件面板：协商 `兼容 · schema 1 · OK`、注册 `sample-effects@1.0.0`、brightness `{brightness:0.5}`、ping `{pong:7}`。
  - 脚本控制台：`ocx.capabilities` 执行返回 `0.1.0` + discover 能力列表。
  - 截图 `roadmap/oc-core-lab.png`（三面板全展开）。

### 踩坑

- 折叠 `<details>` 下的按钮在 `snapshot -i` 中不可见，须先点 summary 展开再读取交互 ref。

### 诚实边界

- `/core-lab` 是 dev/test 期验证台，不是产品功能页；页面文案已明示「产品编辑请使用 /editor」。
- 第一档 B 的插件面板已从 `/editor` 迁至 `/core-lab`（此前在 editor Settings 验收过一次），迁移后在本页重新验收通过；`/editor` 不再承载任何 core 验证面板。
