## W-08 第七批：Firefox 音频兼容回归（Web 稳定性）

### 背景

- 用户指示「先完善 web 版本，把 web 做好，做稳定」，暂停桌面 W-14，回到 Web 唯一剩余 DoD：Firefox 音频兼容。
- 官方一手查证（MDN `WebCodecs_API/Codec_selection`）：AAC `mp4a.40.2` 编码支持 90.1%，**Firefox 全平台不支持**；Opus 96.1% 广泛支持。`AudioEncoder.isConfigSupported` 是 Limited availability 特性。
- 探查发现关键缺口：`editor-actions.ts` 原逻辑在音频编码探测失败时**静默导出无声视频**，违反 `PRIORITY.md` L215「禁止静默失败」与降级链 `avc+aac → vp9+opus → 仅视频 → 明确报错`；仓库仅有 Opus 侧「无 AudioEncoder」用例，无 AAC 侧、无 Firefox 回归。

### 实现

- 新模块 `export-fallback.ts`：纯函数 `resolveExportPlan` 按 `webCodecsSupported / aacSupported / opusSupported / container / includeAudio / hasMediaAudio` 决策实际容器、是否带音轨、中文降级提示与阻断错误；MP4+AAC 不可用但 Opus 可用时自动切 WebM 保音轨，WebM+Opus 不可用但 AAC 可用时反向切 MP4，两者都不可用才无声且给明确提示。四种提示文案提为命名常量。
- `editor-actions.ts` `handleExport`：探测三种能力后统一走 `resolveExportPlan`；`plan.error` 阻断；`plan.withAudio` 决定 `buildTimelineAudio`；实际容器决定 exporter 与 `exportFilename`；降级提示进入 running/done 消息。
- `editor-ui.tsx` TopBar：running 态新增 `data-testid="export-fallback-notice"` 黄色提示；done 态新增 `data-testid="export-result-message"` 显示完整结果（此前 done 态只显示下载链接，提示完全不可见）。
- `audio.test.ts`：补 AAC 能力探测 4 项（无 AudioEncoder、模拟 Firefox `supported:false`、支持时参数断言、探测抛异常静默降级），用 `vi.stubGlobal` + `afterEach(vi.unstubAllGlobals)`。
- 新 `export-fallback.test.ts`：9 项覆盖降级链全分支（能力齐备、无 WebCodecs、MP4→WebM、双编码不可用、WebM 原样、WebM→MP4、用户关音频、无音轨、错误优先）。

### 验收

- Web vitest **34 文件 / 428 项**（原 415，+13）、`tsc --noEmit` 0 错误、`vite build` 两个产物均成功。
- 真实浏览器（agent-browser）：注入 `AudioEncoder.isConfigSupported` 使 AAC=false / Opus=true 模拟 Firefox → `Demo` 生成含音轨素材 → 点「导出」（用户默认 MP4）→ 顶栏显示「已导出 90 帧 · 3.00s · 含 Opus 音轨 · 当前浏览器不支持 MP4 音频编码（AAC），已自动改用 WebM + Opus 保留音轨」与「下载 WebM」链接；`data-testid=export-result-message` 断言通过。截图 `roadmap/oc-w08-firefox-audio-fallback.png`。
