## 探查结论（决定方案边界）

- `ocx_domain::read_classic_project`（`local/crates/ocx-domain/src/project_compat.rs:253`）可直接读 v31 JSON → `ProjectView`（画布尺寸/帧率/时长/场景/轨道/元素）。
- `ocx_render::render_frame` 产 CPU RGBA8 演示帧；`FrameParams` 目前只能手写常量，没有 element→params 映射。
- `ocx-editor-api` 的 `SceneSnapshot` 只有 clip_count/label，无现成「项目→可见元素→帧」链路。
- Web 正式模式预览像素是 TS 本地合成（浏览器解码素材帧 + 采样/变换/遮罩/文字栅格化），core WASM 只做项目解析与验证模式演示帧。
- 结论：**不复刻 Web 素材合成管线**（那是后续独立工作），本批按 ADR-04 过渡态做项目骨架联动：profile/时长/帧率从项目 settings 派生，播放头驱动帧号，帧仍是 core 演示合成（文档如实标注）。fixture 的 `params` 全为空，不编造颜色/位置映射。

## 实现

- 新增 `apps/desktop/src/project.rs`：`ProjectState`（view + playhead_ticks + selected_element_id）、`load`/`load_demo`、`profile()`（画布/帧率取项目 settings）、`frame_index()`、`seek`/`select`、`visible_element_at`（主轨优先）、纯函数 `element_visible_at`/`clamp_ticks`；6 项单测。内嵌 fixture 用 `include_str!` 指向 Web 同一份 v31 资产。
- `spike.rs` 的 `spike_params()` 改名为公开的 `demo_frame_params()` 供项目预览复用；`frame_to_render_image` 提升为 `pub(crate)`。
- `shell.rs`：四个面板共用同一个 `Entity<ProjectState>`（GUI 实体共享，一处更新全面板可见）。
- `browser.rs`：项目名 + 轨道/片段列表，点击片段更新共享选中。
- `inspector.rs`：选中元素 id/name/type/start/duration/trim/media 只读展示，未选中给提示。
- `timeline.rs`：时间码（秒/帧）+ 可见元素 + 逐帧 ◀/▶ 按钮 + 片段条点击定位。
- `preview.rs`：按共享播放头重建帧，`cached_key=(帧号,宽,高)` 变化时重算，避免每帧 63ms 重复生成；底部标注「core 演示合成，非素材帧」。
- `Cargo.toml` additive 加 `ocx-domain`/`ocx-time` 路径依赖。

## 关键踩坑

- **轨道判定**：`TrackView.track_type` 取 JSON 的 `type`（main 轨是 `video`、overlay 是 `text`），不是轨道 id。最初用 `track_type == "main"` 导致 t=0 命中 overlay 的 `title-a`；改用 `track.id == "main"`（经典版固定 id）。
- **GPUI API**：`RenderImage` 来自 `gpui` 而非 `ocx_render`；`ElementId` 不接受 `String`，需 `SharedString::from(format!(...))`。
- **借用冲突**：render 里先 `let state = self.project.read(cx)` 会借住 `self.project`，不能直接 `self.rebuild(&mut self)`；改为在 block 内取出数据并复制，结束借用后再重建。
- **DPI 坐标**：原生窗口鼠标自动化中 `SetCursorPos` 受 Windows DPI 虚拟化影响，点击 Browser 片段成功（Inspector 更新），但 Timeline 逐帧按钮未稳定命中；`seek` 纯函数已有单测覆盖，如实记录端到端未复现。
