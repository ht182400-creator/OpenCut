## 追加：L3「上游六项能力落地」收敛预案（2026-11-08）

用户追问：上游真把 Editor API / 插件优先 / Rust core 多端 / MCP / Headless / scripting tab 都实现了，本地 fork 怎么同步、冲突怎么处理。

**核心结论**：这不是合并冲突而是**双实现收敛**；`git merge` 无冲突标记 ≠ 可用，两套 Editor API/插件宿主/MCP 同时注册会造成静默语义冲突。顺序必须是「先定主体 → 再预演 → 再选择性移植 → 最后合并」。已写入 `roadmap/README.md` §7.9（10 个小节）、风险 R11、ADR-09、热点 H13。

**官方核实**（本次抓取/检索）：
- `git merge-tree --write-tree [--name-only] <branch1> <branch2>`（Git ≥2.38）**不读写工作区/索引、不产生提交**；退出码 0=干净 / 1=有冲突；输出第一行为结果树 OID，其后为冲突文件；官方明确「空冲突列表 ≠ 干净合并」、不要覆盖 `--merge-base`（多 base 时可能丢一侧改动）。
- `.gitattributes` 的 `merge=ours` 需自定义 driver（`git config merge.ours.driver true`），仅适合纯本地配置；`union` 两侧行都留但顺序随机，**不可用于代码/结构化配置**。
- 社区「forking trap / clone-and-own」共识：差异台账（divergence ledger）、能上游化的尽量上游化、避免长期双实现。

**新增决策**：
1. 决策门三路线：A 本地为主 / **B 切换到上游（推荐终局，本地差异改写为插件）** / C 双轨过渡；建议 C→B。
2. **细化 §7.3 的命名空间隔离**：上一版建议「新 crate 放 `crates/<新crate>`」不够，因为上游也会用 `crates/*`；改为 `local/crates/*`（Cargo members 追加式显式列出）、crate 名 `ocx_` 前缀、`apps/local-*`、CLI `ocx-render`、MCP 工具前缀 `ocx.*`、Web 组件 `apps/web/src/local/`。所有调用经 `editor-api` 薄适配层。
3. 建纯净镜像分支 `upstream-mirror`（只 fast-forward、永不提交本地改动）作为三方 diff 基线。
4. 能力级差异台账（六行，上游真实路径/SHA 落地后填，不预填猜测）。
5. 五类冲突处理：追加式配置保留双方 / 同名不同实现另存对比后改名 / 静默语义靠 CI+冒烟 / 依赖漂移逐项 `cargo update -p --precise` 不整体覆盖 lock / 删除重命名从镜像取回旧文件到 `local/vendor/`，生成文件重新生成。
6. **skill 脚本边界**：`sync-upstream.ps1` 只适合 L1/L2；L3 不要直接跑（它不会做能力级决策）。
