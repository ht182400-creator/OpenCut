## W-05 第三批：animation 关键帧插值（用户「继续」，2026-11-09）

**Why**：用户连续多轮要求「继续」，按 `PRIORITY.md` 的 P0 关键路径，ripple 与 placement 两批之后继续翻译经典版纯函数，累积领域回归网，为 W-06 的 Web 绑定铺路。

**交付**：`local/crates/ocx-domain/src/animation.rs`（贝塞尔求解 4 函数 + interpolation 的归一化/外推/三种段求值/离散通道/统一分派），配套 `tests/{animation_golden_master.rs,animation_unit.rs,animation-reference.mjs,animation-alignment.test.mjs,ANIMATION_CASES.md,fixtures/animation_cases.json}`。经典版路径是 `apps/web/src/animation/{bezier,interpolation}.ts`；`keyframe-query.ts` 依赖 `channel-data.ts` 与 `params` 颜色格式化，本批不做并已注明。

**关键决策（跨语言浮点）**：经典版 `solveBezierProgressForTime` 只做 20 次二分，固有误差约 `4.8e-7`，经数值缩放后约 `5e-6`。最初设 `1e-9` 容差会误判，改为 **`1e-5`**（仍远小于任何逻辑错误）。Rust 与 JS 两侧都实现**递归容差比较**：数值按绝对误差、对象/数组逐项、其余严格相等。这解决了 `serde_json::Number` 的 `Float(0.0)` 与 `PosInt(0)` 不相等、以及跨语言最短小数表示差异两类问题。

**判别方式差异**：经典版 `isScalarChannel` 靠 `extrapolation` 字段或 key 的 `segmentToNext`；Rust 用 `#[serde(untagged)]` 按 value 的数值/布尔字符串类型判别，JSON 结构保持经典版原样（无额外 `kind` 字段）。语义等价并记录在 `NOTICE.md`。

**验证**：四 crate `fmt --check` / `clippy -D warnings` / `cargo test` 全绿；`moon run ocx-domain:test`（proto 管理、无 FORCE_GLOBALS）退出码 0；JS 三套对齐 **animation 88/88、placement 100/100、ripple 64/64**，契约 5/5、看板 44/44、兼容契约 45/45；42 个文档链接 0 失效；lints 0；代码文件均 ≤500 行。累计 72 个 JSON golden 用例、13 个补充单测。

**踩坑**：clippy `unnecessary_sort_by` 两处改 `sort_by_key`；`animation_unit.rs` 初版把稳定排序后的帧顺序断言写错（实际 a→c→b），已修正。

**How to apply**：继续按同一模板（JSON fixtures + Rust golden master + JS 参考实现 + CASES.md + 补充单测）翻译剩余领域逻辑；每次新增浮点结果都要评估迭代算法固有精度再定容差。下一批可做 `keyframe-query` 或转向 W-06 Web 绑定薄层。
